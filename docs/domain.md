# 领域资料

绕标赛与长航赛使用不同江段，赛道浮标、船只检修、天气观测和救援覆盖共同决定能否发令。

外部主体使用不含真实身份信息的引用编号。交换时间采用带偏移量的 ISO 8601 字符串，原始材料只保存受控引用（如 `observation_ref`、`checkpoint_ref`）或 `sha256` 摘要（如 `summary_sha256`）。`contracts/entities.json` 中的字段名称属于稳定接口约定，运行时数据文件位置由 `DATABASE_PATH` 决定。

## 唯一权威状态源

本服务是赛事安全状态的唯一权威来源，直播端、裁判台、救援队都以其决定为准。

### 双时间轴

每条事实同时记录两个时间：

- `occurred_at`：事实实际发生时间，由上报方提供，必须带 UTC 偏移量；
- `recorded_at`：服务端受理时间，系统填写。

事实**只能追加**（append-only），不得删除或就地改写；更正以一条更新的事实表达。

### 发令瞬间点时间判定

某赛段能否开放，只取决于发令瞬间 `T = occurred_at` 各前置条件是否有效，评估时只采信 `occurred_at <= T` 的最新事实：

1. 赛道版本：已发布、`confirmed=true`，且版本对应的江段与赛段江段一致（防止次日长航赛沿用绕标赛旧江段）；
2. 风速观测：存在、在赛段观测时效窗口内、数值在限值内；
3. 能见度观测：同上，且不低于下限；
4. 救援覆盖：赛段 `required_zones` 中每个救援区在本江段都有"就位"记录（旧江段的区不算数）；
5. 每个未退赛船队：本赛段已报到、船只检修通过、培训完成；
6. 赛段不处于暂停状态。

每次 `/start` 或 `/resume` 都会留存**判定瞬间完整依据快照**（含赛道版本、观测编号、各事实的发生与受理时间），即使被拒绝也留档。快照一旦写入不可变——之后受理的迟到观测不会改变发令瞬间的判定。

### 暂停与恢复

开放后的赛段可因浮标移位、天气等暂停。暂停一旦录入，公众视图立刻变为 `suspended` 且 `ready=false`，杜绝"裁判台已暂停、直播端仍显示可以出发"。恢复开放必须调用 `/resume`，在恢复瞬间**重新确认全部前置条件**（新赛道版本、时效窗口内的新观测、救援就位等），确认通过才清除暂停。

### 航次冻结与迟到事实

裁判签署比赛结果后赛段冻结：

- 实际发生时间晚于签署时间的事实一律拒收（迟到观测不得改写已结束航次）；
- 实际发生时间更早、但受理较晚的补录允许保存，用于事后追溯，但不改变冻结结果；
- 进行中航次的公众视图锚定最近一次成功发令/恢复的依据快照，而不是用查询时刻去重算历史观测。

### 退赛

船队退赛后退出后续发令门（不再被要求报到/检修/培训），但其此前的报到与检查点记录全部保留，并出现在公众视图的 `progress` 中。

### 角色边界

| 角色 | 能力 |
| --- | --- |
| `judge` 裁判 | 登记配置、录入裁判域事实、发令/恢复、签署结果、查判定记录 |
| `rescue` 救援 | 仅维护救援覆盖（`rescue-coverage`）与安全事件（`safety-incident`） |
| `public` 公众 | 只读当前权威决定，决定中带依据版本与更新时间 |

公众决定中的每个状态都带 `updated_at`（所依据事实的最新实际发生时间）、`basis`（逐项证据）与 `reasons`（未满足项）。
