# 领域资料

绕标赛与长航赛使用不同江段，赛道浮标、船只检修、天气观测和救援覆盖共同决定能否发令。

外部主体使用不含真实身份信息的引用编号。交换时间采用带偏移量的 ISO 8601 字符串，原始材料只保存受控引用或 `sha256` 摘要。`contracts/entities.json` 中的字段名称属于稳定接口约定，运行时数据文件位置由 `DATABASE_PATH` 决定。

## 权威模型：只追加事件 + 时点判定

所有事实（船队报到、船只检修、培训、赛道版本、风速、能见度、救援覆盖、安全事件、暂停/恢复、检查点、退赛、发令、签署）都以事件形式按**实际发生时间** `occurred_at` 写入，服务只追加、不修改、不删除；每条事件携带上一条的 `entry_hash`，形成按赛段串联的哈希链，`event_id` 幂等去重。事件晚到（迟到观测）按其 `occurred_at` 在时间轴上归位。

**发令（`start_commanded`）是唯一的开放关口。** 服务在发令瞬间对该赛段求值，只采用 `occurred_at <= 发令时刻` 的事件，七项前置条件全部有效才开放：

| 前置条件 | 有效含义 |
| --- | --- |
| `course_current` | 已有发布的赛道版本（浮标配布 + 救援江段清单） |
| `wind_within_limit` | 最新风速观测 `wind_speed_kt <= limit_kt` |
| `visibility_adequate` | 最新能见度观测 `visibility_m >= minimum_m` |
| `rescue_covered` | 当前赛道版本列出的**每个江段**都有同版本 `covered=true` 声明 |
| `no_active_safety_incident` | 当前江段无 `active=true` 的安全事件 |
| `not_suspended` | 最新赛段管控事件不是暂停 |
| `fleet_ready` | 至少一支已报到且未退赛船队检修合格、培训完成 |

开放决定连同当时的完整依据（每项条件的观测值、时间、证据事件号）**一次性冻结**。此后任何迟到观测、补报都只追加留痕，不能改写开放状态与依据；重复发令被拒绝。发令被拒不冻结，条件补齐后可重新发令。

## 关键规则

- **暂停与恢复**：裁判台 `leg_suspended` 后，直播端立即看到 `state=suspended/open=false`，暂停期间发令被拒。恢复事件必须带 `reconfirmed=true`（对全部前置条件的重新确认），否则服务端拒绝；恢复本身不自动开放，发令瞬间仍按当时条件重新求值。
- **赛道版本与救援覆盖**：救援覆盖声明绑定 `(rescue_zone, course_revision)`。赛道换版后，救援队手里的旧江段信息不满足新江段清单，必须按新版本逐江段重新声明，长航赛才可能开放。
- **退赛**：退赛船队不阻塞赛段、不进入发令名单，但退赛时刻之前的检查点记录全部保留，并出现在裁判签署的结果快照中；退赛之后的打卡不计入。
- **签署终局**：只有已开放赛段可由裁判 `result_signed`，签署后公众视图为 `result_signed`，之后到达的事件状态为 `recorded_not_authoritative`，不改写结果。
- **角色隔离**（服务端强制）：裁判（`race_referee`）独占暂停/恢复/发令/检查点/签署；救援协调员（`rescue_coordinator`）只能写救援覆盖与安全事件；报到、检修、培训、赛道、天气分别由对应角色写入。越权写入返回 `role_forbidden`。
- **公众查询** `GET /v1/legs/<leg_ref>/decision`：返回当前决定 `state/open`、`updated_at`（开放时为发令时刻、签署后为签署时刻、未开放时为最新接收时间）与 `decision.basis` 依据版本，供直播端与公众直接展示。
